# บทสนทนาและปฏิกิริยาตามวัย — ข้อเสนอสำหรับตรวจแบบ

สถานะ: แผนเสนอ ยังไม่อนุมัติให้แก้เกม งานสำรวจใช้ sub-AI สองตัวแบบอ่านอย่างเดียวแล้ว

## เป้าหมาย

ให้คนเป็นตอบสนองต่อซอมบี้เด็ก วัยรุ่น ผู้ใหญ่ และผู้สูงอายุต่างกันอย่างเหมาะกับฉาก โดยรักษาความกลัว ความไว้ใจ ความหิว สติ และผลการตัดสินใจเดิม ไม่เพิ่มการแยกเพศในระบบบทสนทนารอบนี้

ใช้ช่วงวัยที่มีอยู่ใน characterPool.ts: เด็ก 10–12, วัยรุ่น 13–19, ผู้ใหญ่ 20–59, ผู้สูงอายุ 60–80 ไม่ต้องเพิ่มข้อมูลอายุในเซฟ

## แนวทางที่เลือกเสนอ

พิจารณาสามแบบ: เติมประโยคตามวัยชุดเดียวทุกฉาก (ทำง่ายแต่ซ้ำและผิดบริบท), ทำสำเนาทุกเหตุการณ์สี่ชุด (ตรวจยากและเสี่ยงผลเกมแตกต่าง), หรือเพิ่มข้อความเฉพาะส่วนแยกจากเหตุการณ์เดิม

เสนอแบบสุดท้าย: เหตุการณ์ เงื่อนไข ตัวเลือก และผลระบบมีชุดเดียว ส่วนข้อความที่ต้องต่างตามวัยอยู่ในคลังแยก ใช้ข้อความเดิมเมื่อยังไม่มี variant

เกือบทุกฉากที่มีคนตอบสนองต่อผู้เล่นต้องผ่านการตรวจตามวัย แต่ไม่บังคับให้ทุกประโยคพูดเรื่องอายุ ฉากอ่านป้าย ค้นลัง หรือพบสิ่งแวดล้อมล้วนสามารถใช้ข้อความกลางพร้อมเหตุผลในรายงาน coverage

## โครงสร้างข้อมูลและจุดเชื่อม

- ผู้รวบรวมกำหนดกุญแจ `sourceFamily / eventId / choiceId / field` ก่อนแจกงาน ไม่ใช้ลำดับ array เป็นกุญแจถาวร จุดที่ไม่มี choiceId ให้เพิ่มกุญแจคงที่เฉพาะข้อความที่จะปรับ
- แต่ละรายการเก็บข้อความฐาน บริบท ผู้พูด และข้อจำกัดที่ AI ต้องรู้ ผลส่งกลับมีเฉพาะกุญแจ กลุ่มวัย และข้อความ ห้ามส่ง effects หรือเงื่อนไขใหม่
- เพิ่ม resolver กลาง เช่น src/data/ageDialogue.ts โดยใช้อายุจาก characterProfile/currentBio ที่ผ่านการตรวจแล้ว มี fallback ต้นฉบับและไม่สุ่มคำใหม่ทุก render
- แยกไฟล์ข้อความตามเจ้าของงาน เช่น src/data/age-dialogue/npc.json, travel.json, events.json เพื่อให้ writers ทำพร้อมกันโดยไม่ชนไฟล์
- ฝั่ง engine ต้องครอบคลุม pendingEvent, choose และข้อความที่บันทึกลง log ผ่านจุดเชื่อมที่ sync-bangkok-content.mjs สร้างให้ ไม่ให้ writers แก้ bundle โดยตรง
- ฝั่ง LifeSim resolve หลังประกอบข้อความตามบริบทเดิม แต่แยกข้อความใช้แสดงออกจากข้อมูลที่ handler ใช้คำนวณผล
- App.tsx ต้องใช้ข้อความที่ resolve เดียวกันในหน้าต่าง ผลหลังเลือก recordStoryResult และ log ที่เซฟไว้
- StoryFeed แสดงข้อความที่บันทึกตอนเกิดเหตุการณ์ ไม่คำนวณวัยย้อนหลังให้เรื่องเก่าใหม่ อายุในความทรงจำชีวิตก่อนต้องแยกจากอายุผู้เล่นปัจจุบัน

## ความเสี่ยงที่ต้องแก้ก่อนเขียนเนื้อหาจำนวนมาก

App.tsx ใช้คำใน modal.title/text/outcomeText เช่น ฝน หนาว ยิง กระสุน เพื่ออนุมานสาเหตุการตาย ดังนั้นการเปลี่ยนสำนวนอาจเปลี่ยนผลเกมแม้ effects เท่าเดิม ต้องให้กลไกนี้อ่าน canonical text เดิมก่อนใช้ age variant แสดงผล หรือใช้ cause code เดิมที่ยืนยันได้จากเหตุการณ์ ห้ามให้ข้อความที่ AI เขียนเป็นตัวตัดสินกลไก

prepareNpcModal มีหน้าที่เตรียมผลความสัมพันธ์จริง ต้องไม่ใส่การเปลี่ยน effects ตามอายุลงในฟังก์ชันนี้ การเปลี่ยนคำพูดเกิดหลังการตัดสินกติกาเดิมแล้ว

## กติกางานเขียนร่วมกัน

1. NPC เห็นลักษณะวัยโดยประมาณ ไม่รู้เลขอายุจริงโดยไม่มีการบอก
2. เด็กยังเป็นซอมบี้ที่อันตราย ไม่มีสิทธิ์ได้เข้าใกล้หรือได้รับความไว้ใจเพิ่มฟรี
3. ผู้สูงวัยไม่จำเป็นต้องอ่อนแอ สับสน หรือฉลาดกว่าคนอื่น ไม่แต่งเรื่องลูกหลานหรืออดีตเพิ่ม
4. ไม่เรียกลุง ป้า ตา ยาย โดยอนุมานเพศ ใช้คำเรียกที่ไม่ต้องแยกเพศ
5. ความไว้ใจ ความหิว สติต่ำ ชื่อเสียง อาชีพ และเหตุการณ์ที่เกิดจริงมาก่อนยังสำคัญกว่าสำนวนตามวัย ห้ามทำให้ตัวละครสติต่ำพูดคล่องขึ้น
6. รักษาคำเตือน ระยะปลอดภัย เจตนา และข้อเท็จจริงในข้อความฐาน เปลี่ยนเฉพาะคำพูด น้ำเสียง หรือปฏิกิริยาที่สอดคล้องกับวัย
7. ไม่เติมคำกล่าวถึงเด็ก/คนแก่ลงทุกบรรทัด โดยเฉพาะวิทยุ การตะโกนจากที่มืด หรือฉากที่ผู้พูดมองไม่เห็นผู้เล่น
8. Titles, notes และข้อความอธิบายเงื่อนไขไม่ต้องมี variant ตามวัยโดยอัตโนมัติ ตัวเลือกผู้เล่นเปลี่ยนเฉพาะจุดจำเป็น ไม่เพิ่มหรือตัดทางเลือก

## ลำดับงานหลังอนุมัติ

1. **สำรวจและแบ่งรายการ:** ส่งรายชื่อข้อความไม่ซ้ำ พร้อม source และ stable IDs จัดประเภทต้องมี variant / ใช้ข้อความกลาง / ไม่มีผู้ตอบสนองให้ผูกวัย และระบุเจ้าของแต่ละรายการก่อนเขียน
2. **ทำระบบเชื่อม:** integrator สร้าง resolver และเชื่อม UI/ผลลัพธ์/log โดยมีต้นฉบับเป็น fallback พร้อมป้องกันกลไกที่อ่านคำในข้อความ
3. **Pilot 12 ฉาก:** NPC หกจังหวะ บทเดินทางสามฉาก เหตุการณ์ต่อเนื่องที่มีคนเป็นสามฉาก ใช้สี่วัยเดิมและตรวจเทียบฉากเดียวกันทุกวัย ผู้ใหญ่ใช้ข้อความเดิมได้ถ้าเหมาะแล้ว
4. **จุดตรวจคุณภาพ:** ส่งตัวอย่างสี่วัยให้ผู้ใช้พิจารณาน้ำเสียงก่อนขยาย ตรวจว่าไม่ได้กลายเป็นแค่เปลี่ยนคำเรียกหรือเติมประโยคซ้ำ
5. **ขยายเป็นชุด:** ส่งงานครั้งละประมาณ 10–15 ฉากต่อ writer รวม ตรวจ และทดสอบทีละชุด ไม่มีการเขียนหลายร้อยบรรทัดแล้วรวมครั้งเดียว
6. **ปิด coverage:** ทุกฉากในบัญชีต้องมีสถานะครบแล้ว/ตั้งใจใช้ข้อความกลาง/พักไว้พร้อมเหตุผล ขยายไปบทจบและชีวิตก่อนหลังแนวทางหลักนิ่ง

## การตรวจรับ

- อายุขอบเขต 10,12,13,19,20,59,60,80 เข้ากลุ่มถูกต้อง; ตัวละครชาย/หญิงวัยเดียวกันไม่เปลี่ยนเพราะเพศ
- ฉากเดียวกันตรวจวัยทั้งสี่ร่วมกับความไว้ใจต่ำ/สูง สติปกติ/ต่ำ และประวัติช่วยคน/ฆ่าคน ใช้ fixtures ที่เจาะจง ไม่สร้างผลคูณทุกข้อความโดยไม่จำเป็น
- ไม่มี variant ใช้ต้นฉบับได้; ไม่พบข้อความว่าง placeholder ค้าง ID ซ้ำ หรือกุญแจที่อ้างฉากไม่มีจริง
- เปลี่ยนสำนวนแล้ว effects, enabled, day, items, flags, saved/killed, NPC state และ cause of death เท่าเดิม สำหรับจุดที่ได้รับการแก้
- เมื่อเปิดหน้าต่างค้าง รีโหลด นำเข้าเซฟ หรือเปิดประวัติย้อนหลัง ข้อความไม่สลับวัยและตรงกับผลที่ผู้เล่นเลือก
- ผ่าน typecheck, build, เทสต์ระบบเดิมที่เกี่ยวข้อง และ browser test ของ engine pending กับ LifeSim อย่างน้อยอย่างละเส้นทาง

ยังไม่เสนอให้มี AI แต่งสดขณะเล่น เพราะจะควบคุมน้ำเสียง ความสอดคล้อง ความเร็ว และการบันทึกซ้ำได้ยากกว่าเนื้อหาที่เขียนและตรวจไว้ล่วงหน้า
