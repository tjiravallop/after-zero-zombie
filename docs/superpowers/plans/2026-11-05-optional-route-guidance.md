**Goal:** ให้ผู้เล่นเลือกเปิดเบาะแสละเอียดและตัวช่วยปักหมุดช่วงท้ายแยกกัน โดยค่าเริ่มต้นไม่มีคู่มือเฉลยเปิดอยู่

**Tech Stack:** React, TypeScript, CSS, Node assert และ puppeteer-core ที่มีอยู่แล้ว

**Spec:** ../specs/2026-11-05-optional-route-guidance-design.md — ผู้ใช้อนุมัติแล้วเมื่อ 2026-11-05

- Codex หลักในแชตนี้: ทำงาน 1–5 ตามลำดับ เขียนโค้ด ทดสอบ และตรวจ diff ทั้งหมด ไม่ใช้ subagent ในแผนนี้

## Global Constraints

- สวิตช์ทั้งสองปิดเป็นค่าเริ่มต้น รวมถึงเซฟเก่าที่ไม่มีค่าตั้งนี้
- สวิตช์เบาะแส ตัวช่วยปักหมุด และตัวเลขผลลัพธ์เป็นอิสระจากกัน
- ไม่เปลี่ยนความหิว ระบบวัน NPC รางวัล หรือเงื่อนไขชนะ
- ไม่เพิ่ม dependencies และไม่แยก App.tsx ใหม่ทั้งไฟล์
- 75% เป็นเกณฑ์เสนอความช่วยเหลือ ไม่ใช่การเปลี่ยนเงื่อนไขจบ

- ไม่เปิดเผยชื่อฉากจบหรือสูตรตัวเลขผ่านตัวช่วยปักหมุดเมื่อปิดเบาะแสละเอียด

### กติกาความคืบหน้า 75% ที่เสนอ

ใช้เฉพาะสามรูทเดิม: vaccine, horde, evolution; ยังไม่คำนวณเปอร์เซ็นต์ให้บทจบส่วนบุคคลหรือแขนง extinction ที่มีเงื่อนไขพิเศษ

1. ต้องทำขั้นเตรียมรูทจริงสำเร็จอย่างน้อย 2 จาก 3 จุดก่อน นับ flag `route.<id>.<index>` ที่เป็นจริง ไม่ใช่การเดินผ่านสถานที่หรือเปิดอีเวนต์แล้วถอย
2. คำนวณค่าเฉลี่ยของสัดส่วนเตรียมงาน, สัดส่วนของแต่ละค่าสถานะที่รูทต้องการ และสัดส่วนตัวอย่างเชื้อถ้ารูทนั้นต้องใช้ ทุกสัดส่วนจำกัดที่ 0–1
3. เสนอคำแนะนำเมื่อค่าเฉลี่ย >= 0.75 โดยเปรียบเทียบค่าจริง ไม่ปัดเป็นเปอร์เซ็นต์ก่อน
4. ไม่นับตำแหน่งปัจจุบันในคะแนน เพราะหน้าที่ตัวช่วยคือพาไปยังจุดที่เหลือ
5. ตัวอย่าง: รูทเซรุ่มเตรียม 2/3 จุด ค่าสถานะทั้งสี่ครบ และตัวอย่างครบ ได้ (2/3 + 1 + 1 + 1 + 1 + 1) / 6 ≈ 94.4% จึงเสนอได้ แต่เตรียมเพียงจุดเดียวจะไม่เสนอแม้ค่าสถานะเต็ม
6. ตัวเลขนี้วัดความพร้อมตามเงื่อนไข ไม่ได้หมายถึงเห็นเนื้อเรื่องครบ 75%; ไม่แสดงเปอร์เซ็นต์นี้ใน UI ปกติ

### เป้าหมายหลังปักหมุด

- เลือกขั้นเตรียมที่ยังไม่สำเร็จตามลำดับเดิมใน JSON; action ID คือ `route.<id>.<index>` ตามตัวสร้างเนื้อหาปัจจุบัน
- ถ้างานอยู่ย่านอื่น ไฮไลต์ย่านปลายทาง ใช้ระบบเดินทางทีละช่วงเดิม ไม่สั่งเดินเอง
- ถ้างานอยู่ย่านปัจจุบัน ให้ปุ่มงานนั้นอยู่ใน “ตรงหน้าเจ้า” และติดป้าย “เป้าหมายที่ปักหมุด” เพื่อไม่ให้ไฮไลต์ถูกซ่อนในเมนูพับ
- ถ้า action ถูกล็อก แสดงเหตุผลที่จำเป็นและไม่ทำให้ปุ่มกดได้โดยฝืนเอนจิน
- เตรียมครบแต่ยังขาดค่าสถานะ: เปลี่ยนเป็นคำแนะนำกว้างตามสิ่งที่ขาด เช่น “ยังต้องศึกษาการตอบสนองของเชื้อ” ไม่สร้างตำแหน่งงานที่ไม่มีจริง
- เตรียมครบและเงื่อนไขพื้นฐานครบ: ไฮไลต์ปลายทางของรูทโดยไม่บอกชื่อฉากจบ; สายฝูงไม่ชี้นำแขนง extinction
- ค่าตกต่ำกว่าเกณฑ์ภายหลัง: ไม่เสนอหมุดใหม่ แต่รักษาหมุดที่ผู้เล่นเลือกไว้และอัปเดตงานที่ยังขาด
- หลายรูทเข้าเกณฑ์: เรียงความพร้อมมากไปน้อย ใช้ลำดับ JSON เมื่อตรงกัน ผู้เล่นเลือกเอง ไม่มีการสลับหมุดอัตโนมัติ
